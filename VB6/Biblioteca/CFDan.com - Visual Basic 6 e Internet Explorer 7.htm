Visual Basic 6 And Internet Explorer 7 Visual Basic 6 e Internet Explorer 7

I am currently moving over to C# .NET for all my desktop programming but I have some legacy apps written in Visual Basic 6 that use the WebBrowser Control extensively. Actualmente me estoy moviendo a C # .NET para toda mi programación de escritorio, pero tengo algunas aplicaciones heredadas escritas en Visual Basic 6 que utilizan el control WebBrowser ampliamente. Plus, sometimes you dont want the overhead of .NET 2.0 just to knock out a quick app so Visual Basic 6.0 works perfectly in some scenarios. Además, a veces usted no desea la sobrecarga de .NET 2.0 sólo para noquear a una aplicación rápida para Visual Basic 6.0 funciona perfectamente en algunos escenarios.

Since I installed Internet Explorer 7 all references to the library that holds the Web Browser control are broken. Desde que he instalado Internet Explorer 7 todas las referencias a la biblioteca que contiene el control de explorador Web están rotos. I see lots of people around the net are having the same issues and there is a simple solution. Veo un montón de gente alrededor de la red están teniendo los mismos problemas y no hay una solución simple.

All you have to do is click Project and then Components, click Browse... and locate shdocvw.dll in the System 32 directory. Todo lo que tiene que hacer es clic en proyecto y, a continuación Componentes, haga clic en Examinar ... y localice shdocvw.dll en el directorio del sistema 32. This will restore the IDE back to referencing the correct .dll for the WebBrowser control and all other projects will load fine from then on. Esto restaurará el IDE de nuevo a hacer referencia a la DLL correcta para el control WebBrowser y todos los demás proyectos se carga bien desde entonces.

UPDATE - Saturday 28th October 2006 ACTUALIZACIÓN - Sábado 28 de octubre de de 2006

I ran into a slight issue that took a while to figure out. Me encontré con un pequeño problema de que tomó un tiempo para averiguar.
On the development machine, the VB6 IDE threw a strange error after the Navigate2 method is called. En el equipo de desarrollo, el IDE de VB6 lanzó un extraño error después de que el método se llama Navigate2. This error was something like "Runtime Exception -1 (FFFFFFF)". Este error fue algo así como "excepción de tiempo de ejecución -1 (FFFFFFF)". I couldnt figure out what it was because when I compiled the app and ran it outside VB IDE I didnt get the error. No pude averiguar lo que era porque cuando he compilado la aplicación y corrió fuera del IDE de VB no pudiera estar el error. After a while I remembered that when I installed IE7 (I did this twice to see what would change on my machine) it reset some basic security settings. Después de un tiempo que recordaba que cuando he instalado Internet Explorer 7 (Lo hice dos veces para ver qué iba a cambiar en mi máquina) que restablecer algunas configuraciones básicas de seguridad. One of these is "Allow scripting of the WebBrowser Control". Una de ellas es "Permitir secuencias de comandos del control WebBrowser". This was the culprit. Este era el culpable. If I checked this on, the IDE didnt throw the error. Si he comprobado en esta, la ni de IDE tirar el error.

Another thing to stress is that the end user of your application will have no problems if your VB6 App uses the WebBrowser control. Otra cosa a destacar es que el usuario final de la aplicación no tendrá ningún problema si su aplicación VB6 utiliza el control WebBrowser. Even if you have IE6 and they have IE7, your app is compatible. Incluso si usted tiene IE6 y IE7 tienen, su aplicación es compatible.
